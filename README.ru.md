# Ежедневник

[English](README.md) · **Русский**

Еженедельник для Android в духе бумажного планера. Один экран — одна неделя: свайпом влево и вправо листаются недели, нажатие на строку — новая задача, галочка — задача выполнена. Работает полностью офлайн и по желанию синхронизируется через файл в Dropbox или на Яндекс Диске.

## Возможности

- **Неделя на экране.** Недели листаются свайпом, круглая кнопка с календарём возвращает к текущей неделе. Сегодняшний день выделен, и при открытии приложения текущая неделя прокручивается к нему.
- **Пишите на строчках.** Нажмите на пустую строку, чтобы добавить задачу, и Enter, чтобы сразу добавить следующую. Нажатие на задачу — редактирование, стёртый текст — удаление.
- **Отмечайте выполненное.** Выполненные задачи становятся серыми и зачёркнутыми. Значок метлы в заголовке дня удаляет все его выполненные задачи сразу, с возможностью отмены.
- **Прочее.** Список задач без даты после воскресенья.
- **Меню по долгому нажатию.** Цветное выделение (пять цветов), перенос на следующий день, на любую дату или в «Прочее», удаление с возможностью отмены.
- **Телефоны и планшеты.** Портретная ориентация: одна колонка на телефоне, две на планшете.
- **Светлая и тёмная темы.** Как в системе или выбранная в настройках.
- **Синхронизация через Dropbox или Яндекс Диск по желанию.** Задачи лежат в отдельной папке приложения в вашем облаке, к остальным файлам у приложения нет доступа.
- **Русский и английский** языки — по языку системы.

## Сборка

Нужны Android SDK с платформой 37 (Android Gradle Plugin скачает её сам, если лицензии SDK приняты) и JDK 17 или новее для запуска Gradle.

```bash
./gradlew :app:installDebug
```

Приложение нацелено на Android 16 (API 36) и работает на Android 8.0 (API 26) и новее.

`./gradlew :app:assembleRelease` собирает сжатый release-APK. Он подписывается, если заданы эти свойства, например в `~/.gradle/gradle.properties` (никогда не в репозитории); без них release-APK собирается неподписанным:

```properties
PLANNER_RELEASE_STORE_FILE=/path/to/release.jks
PLANNER_RELEASE_STORE_PASSWORD=...
PLANNER_RELEASE_KEY_ALIAS=...
PLANNER_RELEASE_KEY_PASSWORD=...
```

Чтобы выпустить новую версию, увеличьте `versionCode` и `versionName` в `app/build.gradle.kts`, соберите release, скопируйте его в `dist/planner.apk` и обновите версию и контрольную сумму в обоих README.

## Настройка синхронизации

Синхронизация необязательна: без неё приложение полностью работает офлайн. Для каждого сервиса нужно зарегистрировать приложение; его публичный идентификатор попадает в сборку через Gradle-свойства, например в `~/.gradle/gradle.properties`. В сборке без идентификатора соответствующий сервис просто не показывается.

```properties
PLANNER_DROPBOX_APP_KEY=...
PLANNER_YANDEX_CLIENT_ID=...
```

### Dropbox

1. В [Dropbox App Console](https://www.dropbox.com/developers/apps) создайте приложение с типом доступа **Scoped access** и **App folder**.
2. На вкладке **Permissions** включите `files.content.read`, `files.content.write` и `account_info.read`.
3. На вкладке **Settings** добавьте redirect URI `db-<app key>://oauth` и скопируйте **App key** в `PLANNER_DROPBOX_APP_KEY`. App secret не используется.
4. Новое приложение Dropbox находится в статусе разработки и работает сразу. Когда к нему подключатся 50 пользователей, Dropbox даёт две недели на бесплатную заявку на production-статус, после чего новые пользователи блокируются.

### Яндекс Диск

1. На [oauth.yandex.ru](https://oauth.yandex.ru/) создайте приложение. Платформа: **Android-приложение**, имя пакета `com.ivanopulo.planner` и SHA-256 отпечаток каждого ключа подписи. Для debug-ключа:
   ```bash
   keytool -list -v -keystore ~/.android/debug.keystore -alias androiddebugkey -storepass android | grep SHA256
   ```
2. Доступ к данным: **Яндекс Диск** → *Доступ к папке приложения на Диске* (`cloud_api:disk.app_folder`) и **Яндекс ID** → *Доступ к адресу электронной почты* (`login:email`).
3. Скопируйте **ClientID** в `PLANNER_YANDEX_CLIENT_ID`.

После этого откройте в приложении **Настройки → Синхронизация** и войдите через любой из сервисов.

### Как работает синхронизация

- Все задачи, включая отметки об удалении, хранятся в одном файле `planner.json` в папке приложения: `Apps/<имя приложения>` в Dropbox, `Приложения/<имя приложения>` на Яндекс Диске.
- У каждой задачи есть время последнего изменения; при расхождении между устройствами побеждает более новая версия, а синхронизация никогда не затирает задачу, изменённую на устройстве во время синхронизации.
- Синхронизация запускается при открытии приложения, через пять секунд после последней правки, каждые 12 часов в фоне и по кнопке — и только при наличии сети.
- Токены хранятся в отдельном файле, который не попадает в резервные копии Android, поэтому восстановленное приложение попросит войти заново.
- Выход из аккаунта оставляет все задачи на устройстве и забывает токен; для Dropbox он ещё и отзывается.

## Архитектура

Одно Activity на Kotlin, Jetpack Compose и Material 3, без DI-фреймворка.

| Слой | Содержимое |
| --- | --- |
| `domain` | `Task`, `TaskColor`, расчёты недель (`Weeks`) |
| `data` | База Room (`TaskEntity`, `TaskDao`), `TaskRepository`, настройки в DataStore |
| `sync` | `SyncEngine` и `TaskMerge` (чистая логика), `DropboxAuth` (OAuth с PKCE) и `DropboxRemoteStore`, `YandexAuth` (Yandex ID SDK) и `YandexRemoteStore`, `SyncManager` и `SyncWorker` (WorkManager) |
| `ui` | Пейджер недель, блоки дней и редактирование на месте, меню задачи, настройки |

Недели — страницы `HorizontalPager`, отсчитанные от недели запуска приложения. Удалённые задачи помечаются, а не стираются, чтобы удаление дошло до других устройств через синхронизацию.

```
app/src/main/java/com/ivanopulo/planner/
├── domain/
├── data/
├── sync/
└── ui/
    ├── components/
    ├── settings/
    ├── theme/
    └── week/
```

./gradlew :app:testDebugUnitTest
